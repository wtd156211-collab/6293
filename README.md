# 扫描线多边形填充（从 0 实现）

起始环境只有本说明、`samples/**` 与 `.gitignore`，没有实现代码。Python 3.13、只用标准库；页面用原生 HTML + 内联 SVG，无构建、无依赖。

## 1. 范围

要做：在仓库根写 `fill.py`，读一份轮廓 JSON，按填充规则算出每个像素行的覆盖区间并输出结果文本；再写自包含页面 `viewer.html`，把结果画成像素图并叠加轮廓。

```
python3 fill.py <轮廓.json>                # 结果写到标准输出
python3 fill.py <轮廓.json> --out <文件>    # 结果写到文件，字节与标准输出一致
```

参数个数不对、JSON 读不动、坐标不是整数、规则不认识、画布尺寸非法时，向 stderr 打印一行以 `error:` 开头的说明，退出码 2，不写输出文件；正常结束退出码 0。

明确不做：抗锯齿、灰度、半透明与颜色混合（像素只有填 / 不填）；浮点坐标、曲线与圆弧；几何/位图库与任何第三方依赖；构建步骤与网络请求；画布之外的像素与随屏幕缩放的画布。

## 2. 口径与公式

### 2.1 坐标与画布

- 原点在左上角，x 向右、y 向下，坐标全为整数。
- 像素 `(i, j)` 的中心在 `(i, j)`：`i` 列号、`j` 行号，都从 0 开始。
- 画布 `W × H`：`i ∈ [0, W-1]`、`j ∈ [0, H-1]`。轮廓坐标任意（含负数、超出画布），求交在数学平面上做，只在输出像素时裁到画布内。

### 2.2 交点

- 边是轮廓相邻两点 `(x1, y1)` 到 `(x2, y2)` 的线段，首尾自动闭合。
- 扫描线 `y = j` 穿过第 j 行像素中心，`j` 为整数。
- 相交条件「下闭上开」：`min(y1, y2) <= j < max(y1, y2)`，交点 `x = x1 + (x2 - x1) * (j - y1) / (y2 - y1)`。
- 水平边（`y1 == y2`）与退化边（两端点相同）不产生交点；相邻或重叠的共线边各算各的，不合并。
- 交点是有理数，用分子、分母表示，排序与比较一律整数交叉相乘，归属判定不得用浮点。

### 2.3 两条填充规则

- `even-odd`：该行交点按 x 升序排成 `x0 <= x1 <= …`，覆盖区间是 `[x0, x1)`、`[x2, x3)`……两两配对。
- `nonzero`：边带方向权重 `w = +1`（`y2 > y1`，向下）或 `w = -1`（`y2 < y1`，向上）；交点按 x 升序，同一 x 先合并再结算，累计权重 `c != 0` 的 x 段为覆盖区间。
- 顶点落在扫描线上：顶点是两条相邻边的公共端点，只会同时计入或同时不计入；极值顶点（两条边同侧）留下两个 x 相同的交点，配对后区间长 0，`nonzero` 下同一 x 先合并（权重一次变 ±2），两种规则都不会多填一行或漏行；同一 x 的重合交点不得把状态翻成区间。

### 2.4 像素判定与裁剪

- 覆盖区间左闭右开：像素 `i` 填充当且仅当 `a <= i < b`，中心落在左端算填、落在右端不算。
- 等价说法：像素 `i` 填充，当且仅当落在 `i` 及其左侧的交点数在 `even-odd` 下为奇数、在 `nonzero` 下累计权重不为 0。
- `[a, b)` 对应的像素段是 `i ∈ [ceil(a), ceil(b) - 1]`，再与 `[0, W-1]` 取交；行内按 i 升序，首尾相接的段合并。

## 3. 数据结构

数据流是「轮廓 → 边表 → 每行交点 → 覆盖区间 → 像素段」，没有状态机。

- 边表：每条边记 `(x1, y1, x2, y2, w)`，按行激活并维护当前与扫描线相交的活性边表；组织方式不限，但要守住第 5 节预算。
- 每行：一组按 x 升序的有理数交点（非零规则下带权重），据此得到一组覆盖区间，再落成像素段 `a-b`（含两端）。
- 输出：行按 y 升序、段按 a 升序，相接的段已合并。

## 4. 输入输出与文件格式

一律 UTF-8；结果文本用 LF 行尾，末行有换行。

### 4.1 输入 `samples/polygons/*.json`

```json
{
  "canvas": [24, 16],
  "fill_rule": "even-odd",
  "contours": [
    [[2, 2], [14, 2], [14, 6], [7, 6], [7, 13], [2, 13]]
  ]
}
```

- `canvas`：两个正整数（宽、高），`1 <= W, H <= 4096`。
- `fill_rule`：`"even-odd"` 或 `"nonzero"`。
- `contours`：至少一条轮廓，每条至少 3 个点，坐标为整数；允许重复点与共线点；孔就是另一条轮廓，挖不挖由规则定，不靠方向。
- `even-odd` 的结果与轮廓顺序、起点、走向无关；`nonzero` 里把某条轮廓反向会改变结果，这是规则的一部分。

### 4.2 结果文本（规范输出）

```
format 1
canvas <W> <H>
rule <even-odd|nonzero>
filled <N>
row <y> <a>-<b> <c>-<d> …
hash 0x<16 位小写十六进制>
```

- `row` 行按 y 升序，只写有填充像素的行；段以单个空格分隔，单像素段写成 `a-a`。
- `filled` 是全部段长之和，即填充像素总数。
- `hash` 是 FNV-1a 64 校验值：偏移量 `0xcbf29ce484222325`、质数 `0x100000001b3`，按顺序吃下所有 `row` 行（含行尾 LF、UTF-8），输出 16 位小写十六进制。

### 4.3 页面 `viewer.html`

单文件、双击即开：内联 SVG，无外部资源、无 `fetch`、无构建。每个填充像素渲染为 `<rect data-pixel="i,j">`，轮廓用 `<polygon>` 画在上层；`?sample=<样例名>` 选样例（如 `viewer.html?sample=06-horizontal-edges`），缺省 `01-concave`。数据内联在页面里，只画 4.2 的结果，不另算规则。

## 5. 性能与验收口径

预算（Python 3.13 标准库、单线程、普通桌面 CPU，冷启动计入）：单份输入最多 20000 条边、画布边长最多 4096；4096 × 4096、约 20000 条边、整体稀疏（平均每条边跨行数一二十以内）的输入单次不超过 10 秒；峰值常驻不超过 512 MiB；复杂度目标 `O(E log E + Σ_j A_j log A_j)`，`E` 边数、`A_j` 第 j 行活跃边数，不许每行全量重扫所有边。

确定性：同一输入用 `PYTHONHASHSEED=0/1/2` 连跑，输出逐字节一致；不得依赖哈希随机化、字典与集合遍历顺序、时钟、locale 或随机数，结果不随轮廓顺序与起点变化。

验收逐条：

1. 逐个样例运行 `python3 fill.py samples/polygons/<name>.json`，退出码 0；
2. 结果与 `samples/expected/<name>.txt` 逐字节一致，`--out` 写出的文件也一样；
3. `viewer.html` 带 `?sample=<name>` 打开每个样例，`document.querySelectorAll('[data-pixel]')` 数量等于该样例 `filled` 值，控制台无报错；
4. 换成等价写法（改起点、改顺序、整体反向）复跑，`even-odd` 的结果不变；
5. 预算三项在基准输入上达标；不得读取 `samples/expected/**`，不得按样例名或坐标特判。

## 6. 样例说明

| 样例 | 场景 | 看什么 |
| --- | --- | --- |
| `01-concave` | 凹多边形 | L 形与 U 形，凹角那一段不许漏 |
| `02-ring-holes` | 多轮廓带孔 | 外框挖掉矩形孔与三角孔 |
| `03-pentagram-evenodd` | 自交 | 五角星，中心互叠处是空的 |
| `04-pentagram-nonzero` | 自交 + 非零 | 同一颗星，中心互叠处被填上 |
| `05-scanline-vertices` | 顶点压扫描线 | 梳齿极值点、向下的尖锋 |
| `06-horizontal-edges` | 水平边 | 一像素高横条、共边矩形、台阶 |
| `07-thin-sliver` | 极细长条 | 一像素宽的斜带、尖锋与竖条 |
| `08-clipped-canvas` | 越界裁剪 | 压住四边、完全在外、跨界的孔 |
| `09-nested-nonzero` | 嵌套与反向 | 同向嵌套实心，反向嵌套挖孔 |

每组 `samples/polygons/<name>.json` 对应同名 `samples/expected/<name>.txt`；`samples/notes.md` 是现场记录。
